## 这次解决的问题

用户在多个 AI 工具与项目中重复维护 MCP，难以判断使用位置、连接情况和配置变化。这个工作区负责导入、保存连接定义、分配目标、检查问题以及撤销本次变更。

最先回答的问题是：我有哪些 MCP、给哪些工具和项目使用、现在需要处理什么。

## 数据与状态

1. **服务定义**：名称、本地命令或远程连接、非敏感参数、凭据需求。保存定义只更新库。
2. **实际目标**：工具 × 全局或具体项目 × 配置条目。相同服务可以有多个目标。
3. **管理关系**：发现已有配置不等于获得修改权；用户明确选择后纳入管理。未知来源不推断其由哪个程序管理。
4. **目标配置状态**：未配置、已配置、有待应用变更、外部变化、写入失败等。
5. **连接检查**：最近一次检查的目标、时间与结果。没有检查时明确显示未检测。
6. **客户端状态**：待授权或重载不能被连接测试结果覆盖；无法观察实际会话时不宣称已生效。
7. **应用记录**：保存实际目标和当时配置快照，独立记录成功、失败与跳过项，后续编辑不改变旧记录含义。

## 可体验的核心流程

| 流程 | 关键行为 |
| --- | --- |
| 导入已有 | 明确扫描来源与范围，查看各配置的位置和差异，选择后纳入管理；不部署新目标、不运行命令。 |
| 添加与编辑 | 区分本地命令和远程连接；支持表单与配置片段，校验必填项；保存不隐式应用。 |
| 分配目标 | 选择工具及全局或具体项目，预览新增、更新、已有与冲突；筛选或勾选不写配置。 |
| 应用与重试 | 按目标显示结果；保留成功项，重试仅处理未完成项；重新核对过期预览。 |
| 检测与修复 | 明确本次检测对象与可能启动命令的含义；给出缺少运行环境、凭据、客户端授权等原因和处理步骤。 |
| 外部变化 | 展示保存基线和当前差异，允许保留外部配置或重新纳入；不静默覆盖。 |
| 撤销 | 只处理本次实际变更；后续外改、复用和无关条目受到保护；不恢复整份旧文件。 |

正常编辑和外部变化要区分：定义更新后，目标仍匹配上次写入基线时可以预览更新；目标自身被外改时才进入冲突处理。导入已有代理连接只保留其入口，不展开或替换它管理的内部服务。

## 首版边界

- 适配候选为 Claude Code、Cursor、Codex。原型中的路径、支持项和连接结果是示例；真实适配矩阵需在研发前按客户端版本核对。现有 Skills 工具数量不代表 MCP 支持数量。
- 凭据在连接上下文中处理，不增加独立凭据中心。日志、预览、导出、设备同步不得携带明文密钥；最终安全存储和客户端凭据传递方式另需技术设计。
- 真实授权交给对应客户端原生流程；原型中的“模拟授权完成”必须明确属于演示，不能作为真实授权成功证据。
- 不做常驻代理、服务进程托管、运行环境自动安装、会话聊天、供应商切换或在线分享。
- Skills + MCP 的组合复用待基础流程验证后接入既有预设体系。本次不更名或扩展正在研发的技能预设，不增加第二套模板。
- 多个管理工具共同修改配置仍存在竞争。写前检查、保留无关项和冲突提示只能降低风险，不能保证其他程序不会随后覆盖。

## 原型与生产的界线

演示服务、路径、授权、运行环境、失败及恢复均为模拟。浏览器中的交互验收只能验证设计行为与布局，不能替代真实文件格式保留、持久化、并发写入、跨平台进程、凭据和客户端集成验收。

下一轮是否进入研发，应在评审后另建明确的开发基线，不直接把本草稿纳入 1.1.0。
