# 按可能失败的行为选择测试

从变化的行为、调用方和测试必须检出的缺陷出发。阅读项目测试政策和可用执行入口。选择足够且尽量少的测试层级，不要求每次变化都覆盖所有层，也不替代项目规定的完整检查。

| 风险或要证明的结论 | 有效证据 | 不能据此证明的内容 |
| --- | --- | --- |
| 解析、默认值、计算、状态转换 | 使用独立期望值，覆盖有意义边界和错误情况的单元测试 | 组件组装、导出或安装后的行为 |
| 组件对数据、顺序、事务或清理的理解不一致 | 经过真实协作组件的集成测试；需要时使用隔离文件系统或数据库 | 打包和启动配置 |
| 导出、依赖组装、启动或构建文件可能不同 | 启动真实 CLI、服务、加载器或公开包入口；使用构建产物时先确保构建是新的 | 被替换的外部服务实际会如何运行 |
| 完整用户流程或远端交互约定可能失败 | 通过真实用户入口的端到端测试；只有结论需要且已获授权时才使用真实外部依赖 | 场景没有走到的路径 |
| 渲染、序列化或协议输出需要稳定 | 审查预期输出或快照，同时独立断言重要含义或副作用 | 新接受的快照内容本身正确 |

“真实入口”检查的是组装后的运行方式，不要求另建一套测试框架。一个子进程集成测试可能已经覆盖它。只改 UI 可能需要浏览器检查；纯解析器变化则可能由单元测试加必需检查覆盖。

## 测试替身与独立期望

- 场景关注自身行为时，可替换昂贵或不确定的外部服务、时间和随机源。要声称兼容某个真实外部服务，就保留独立且获授权的真实检查。真实测试被跳过，仍是证据缺口。
- 加载器、解析器、存储适配器或实现选择本身就是可疑缺陷时，不要将其替换掉。手工组装对象会绕过导出和配置错误；内存存储不能证明真实事务或文件系统行为。
- 从公开行为、已知样例或独立计算选取期望值。调用被测实现生成期望、只断言 mock 被调用，或接受全部新快照，都不能证明结果正确。
- 回归测试或新增防护，应证明旧缺陷或非法样例通过真实测试入口会失败，修复后或合法样例会通过。只在隔离副本恢复缺陷，绝不为错误对照破坏用户工作区。

## 选择检查并报告结果

每个重要风险应说明测试层级、入口、准备方式或替身，以及可观察断言。已有测试能检出问题时复用它，避免只照着私有实现结构写测试。风险涉及并发或清理时，按专门的测试可靠性规则补充覆盖。

区分测试计划与实际执行的测试。执行时在工作笔记保留命令、工作目录、相关配置和观察结果；最终答复只需给出与结论有关的证据。检查实际选中的测试数量和产物新鲜度。计划、源码检查、旧日志或其他 Agent 的摘要，都不等于新的一次成功运行。
