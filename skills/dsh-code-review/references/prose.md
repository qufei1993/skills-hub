# 工程文档与文字质量

围绕读者下一步要做的判断写作。说明读者需要的行为、范围、前置条件、输入输出、默认值、失败和恢复条件。每条事实都应对照负责实现它的代码。解释不明显的行为约定和取舍，删除实现过程复述、重复规则、审查对话，以及已经不能解释结果的废弃推理。

每项事实只有一个当前维护位置，其他入口链接到它。指令靠近适用文件，任务细节放在对应任务文档。文档必须可被发现：正确规则若藏在无法找到的笔记里，同样不起作用。不要把每个任务都扩大成全仓库文字清理。

区分当前行为、提案、决策和历史复盘。确认实际交付内容后才更新提案状态。归档时保留原始事故事实和理由，修复指向它的链接，并记录后继文档。沿用项目约定，不强加统一 ADR 目录。决策记录提供上下文，不能自动否决更新的证据。

必须做语义审查。链接有效、翻译哈希一致、格式检查通过或字段完整，都不能证明事实正确或内容完整。界面文案遵守项目语言资源的维护方式；用户数据、代码和协议标识符不能作为普通文字随意翻译。
