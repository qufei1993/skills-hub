# 在保留行为的前提下简化维护

阅读[项目上下文](references/project-context.md)和[验证证据](references/evidence.md)。涉及保留状态或资源负责方时读[生命周期](references/lifecycle.md)；涉及依赖方向、默认值或扩展点的实际必要性时读[编码规范](references/code-conventions.md)。

1. 明确必须保持的行为：公开入口、受支持版本和数据、错误、顺序、取消，以及当前调用方。审查请求给出建议；实现请求可以落实有依据的简化。
2. 追踪候选抽象、重复状态和兼容路径的实际提供方与调用方，包括动态注册、插件、反射和外部使用者。没有直接文本匹配，不能证明公开 API 无人使用。
3. 优先移除多余的负责方、重复约束、不必要的状态转换或无用选项。解释减少了哪些维护责任。仅仅减少行数，可能掩盖职责或把复杂性转移给每个调用方。
4. 用必须保留的行为要求评估一个具体、更小的设计。已发布数据或调用方需要适配器时保留它，不为猜测中的需求增加兼容逻辑。
5. 需要实现时做聚焦改动，验证真实入口和边界情况。用独立断言比较输出、失败行为和生命周期。维护模型变化时更新其负责文档。

报告减少的维护责任、保留的行为、验证证据，以及阻止进一步简化的兼容约束。不顺带重写无关部分。
