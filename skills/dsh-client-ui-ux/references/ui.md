# UI 与响应式行为

添加设计变量或交互模式前，先检查目标项目的设计系统和已有组件。保留产品语言约定、用户数据和平台语义。视觉与键盘交互使用同一套状态模型。

反馈持续时间应与目的匹配：字段错误靠近字段；需要用户恢复的失败操作持续展示；已完成且不阻塞的事件可用短暂通知。失败后保留草稿和选择。尚未解决的故障，不能只在通知中提供恢复入口。

检查适用的加载、空内容、成功、失败、取消和重复触发状态。浮层需要正确的焦点进入与返回、Escape 行为、可访问控件和安全的背景交互。避免在滚动容器中被裁切，也不要把需要操作的消息放在弹窗后面。

使用真实桌面和窄屏视口、键盘焦点，以及有代表性的长文本和本地化内容。按项目无障碍目标检查溢出、缩放、触控目标可达性和窗口安全区域。验证当前实际运行的构建并查看截图；CSS 改动或 DOM 断言本身不等于视觉验证。

DSH 的具体尺寸、字体和审批角色属于其项目选择。应根据目标项目已有设计和测量结果选值，不直接复制常量。
