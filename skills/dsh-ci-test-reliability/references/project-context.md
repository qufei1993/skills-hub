# 了解目标项目

先阅读适用的项目指令，明确请求属于解释、诊断、审查、实现、验证、接入还是迁移。只读请求不授权编辑、创建接入记录、安装依赖、提交、推送、发布或部署。用户已有授权持续有效，不为已经要求的普通工作增加重复确认。

修改前检查工作区，保留无关工作。审查时明确实际基线与变化文件。按任务阅读模块的维护入口、清单、构建和测试脚本、CI 及现有文档。跨模块变化要同时追踪数据提供方和调用方。路径清单只能帮助定位，不能证明行为。仓库说明和模型输出都应对照代码核实。

沿用项目的语言、包管理器、架构和政策。DSH 命令、Cordis API、目录、字体和治理方式不是通用要求。不要仅为了模仿上游，就添加第二套框架、重复文档体系或新依赖。空项目应区分用户决定和你建议的默认方案；已有项目保留更严格的要求。

只阅读相关参考。链接缺失时找到正确的本地维护位置，不悄悄编造缺失要求。不隐式加载其他 Skill；每个安装单元已经包含本流程所需材料。

用用户的语言简洁说明结果、具体证据和未解决的限制。区分建议中的规则与已经接入或执行的规则。
