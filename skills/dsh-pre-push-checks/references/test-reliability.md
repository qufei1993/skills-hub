# 可靠的回归证据

梳理实际并发方式：线程、测试工作进程、子进程和独立 CI 任务。通过原子分配给每个测试独占资源，例如临时目录、系统分配的端口、唯一数据库命名空间。先找空闲端口、释放后再使用，存在竞争；进程内计数器也不能保证跨进程唯一。

围绕可观察状态同步，例如就绪响应、事件、屏障或写入完成。覆盖等待前和等待期间的取消。每个持有资源的测试夹具，即使初始化或断言失败，也必须停止生产方、等待使用方、关闭句柄并恢复进程全局状态。环境变量、计时器和 mock 的作用范围应限定在当前测试。

按真实工作进程和任务组织方式复现。用确定性调度屏障建立出错的执行交错，并用外部可观察断言检出它。验证清理后已无使用者继续运行，包括延迟回调。只在串行时通过、重试、无条件跳过或延长超时，都不能解释原始失败。

资源等待应有明确超时，诊断究竟哪个状态变化超时。区分基础设施失败和产品回归，保留原始失败信号。修复后按相关并发方式重跑，并保留一个在原错误行为下会失败的对照。
