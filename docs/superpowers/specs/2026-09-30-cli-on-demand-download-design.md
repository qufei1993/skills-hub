# CLI 按需下载安装设计

日期：2026-09-30

状态：待审阅；已确认产品方向，尚未批准实现设计。

## 目标与已确认范围

用户希望缩小桌面安装包，并让桌面版发布页面只展示桌面安装与更新所需文件。桌面包不再携带 CLI 可执行文件。用户点击「启用 AI 管理」后，由应用下载当前平台对应版本的 CLI、校验并安装，继续配置终端命令与官方管理 Skill。

现有 CLI 功能、共用数据库、目录与写锁保持兼容。中央 Skill 目录缺失时无法撤销同步的问题继续延期。本次不调整产品版本号，不公开当前 v0.11.0 草稿，也不移动或删除现有版本标签。

## 发布位置选择

推荐建立公开的 `qufei1993/skills-hub-cli` 资源仓库，仅存放 CLI 发布说明和版本文件；源码、编译和测试仍在 `skills-hub` 仓库维护。桌面仓库的 Release 不再附带独立 CLI 和 CLI 校验文件。

替代方案是在现有仓库创建独立 CLI Release：不需跨仓库发布权限，但用户浏览仓库的版本列表时仍能看到 CLI。根据用户希望精简桌面仓库下载入口的目标，推荐独立资源仓库。最终位置在本设计审阅时确认；实现只选择其中一种，不增加用户可配置的下载仓库。

资源仓库必须公开，否则桌面端匿名下载安装无法工作。草稿不能用作公开下载源。仓库创建和发布权限配置在实现阶段进行；本设计阶段不创建远端资源。

## 用户流程

1. 安装或打开桌面端时，不下载或安装 CLI。
2. 设置页面只读取本地 CLI 与官方 Skill 的状态，不发起版本查询、下载、执行 CLI 或读取凭据。
3. 用户点击「启用 AI 管理」或「更新」时，先检查工具与官方 Skill 的安装前置条件，再准备 CLI。
4. 若本地 CLI 已匹配当前桌面要求的版本和哈希，则直接复用；否则下载当前系统和架构对应的文件。
5. 下载期间在现有 AI 管理卡片展示下载、校验和安装状态，禁止重复提交。已知文件长度时展示进度，未知长度时展示阶段及已下载量。
6. 校验成功后使用现有受保护的 CLI 安装目录和原子替换机制安装，再完成官方 Skill 安装或更新及终端配置。
7. 下载失败、文件缺失、哈希不符或替换失败时，显示可重试的本地化说明。保留原来可用的 CLI；不将失败写成已启用。

首次启用需要网络；已安装匹配版本后可离线使用。桌面关闭后 CLI 仍可运行。

## 版本维护

CLI 下载绑定桌面产品版本和编译目标，不使用 CLI 仓库的 `latest` 地址选择桌面所需版本。对应版本未公开或平台文件缺失时返回明确错误，不自动选择其他版本。

桌面启动不再自动下载 CLI，也不先升级官方 Skill。发现本地 CLI 或官方 Skill 版本落后时，设置卡片显示待更新状态，由用户点击完成更新，避免启动新版桌面后先更新官方 Skill、留下旧 CLI。

独立命令行安装脚本仍可从 CLI 资源仓库的最新正式版本安装；这份独立安装保持与桌面管理目录分离。

开发版保持独立 CLI 目录和凭据命名空间。开发时使用本地编译产物及其受验证的调试元数据，不能下载正式版 CLI 到开发目录并将其当作调试版。测试始终使用临时目录与本地 HTTP 服务。

## CLI 元数据与完整性

CLI 构建后生成小型发布清单，包含产品版本、源提交、平台目标、编译 profile、固定资源名称、文件长度和 SHA-256。macOS 或 Windows 如配置代码签名，先签名，再计算长度与哈希。

桌面构建嵌入对应 CLI 的版本、目标、资源名称、长度和 SHA-256，不嵌入可执行文件。预期哈希来自通过原生测试的同一提交的 CI 产物，而不是运行时下载的校验文件。本地正式构建必须提供匹配的清单，缺少或不匹配时构建失败。

应用下载固定版本和固定平台的原始可执行文件，不新增压缩包解压逻辑。接收长度以清单长度为界，拒绝超长或截断内容，流式计算哈希。下载文件置于应用控制的临时目录，校验成功前不执行、不发布为终端命令。

当前 CLI bridge 的目录保护、写锁、受管理文件验证、权限设置、原子替换、版本与哈希记录、失败恢复继续使用。状态检查仍只读取文件，并依据桌面内嵌元数据校验；不以可被修改的本地哈希记录作为唯一信任来源。

## 网络边界

新增下载模块通过 `core/network_proxy.rs` 创建客户端，显式使用应用代理设置。禁用代理时不能继承进程代理。公开下载不读取 GitHub Token、OAuth 凭据或系统安全凭据存储。

下载入口固定为所选公开仓库的版本资源地址，采用 HTTPS。客户端允许 GitHub 下载链路所需的 HTTPS 跳转，拒绝降级为 HTTP，限制跳转次数和总超时。应用通过共享传输模块配置该策略；不在业务模块直接新建客户端或绕过网络边界检查。

错误和日志输出稳定错误码与下载阶段，不记录下载响应正文、凭据或带查询参数的重定向地址。

## 构建与发布顺序

1. 在五个平台原生运行环境上编译、测试 CLI，包括旧桌面数据库兼容性和 Windows bridge 测试。
2. 生成正式 CLI 文件，执行已配置的代码签名和公证，校验命令行版本及启动结果。
3. 汇总最终字节的发布清单、校验文件和二进制，发布到独立 CLI 资源仓库。跨仓库发布身份只通过 GitHub Actions 安全配置提供，不写入仓库、配置文件或日志。
4. 将同一批 CI 元数据交给桌面构建，编译不携带 CLI 二进制的 macOS 两种架构和 Windows x64 桌面包。现有平台支持范围不扩大。
5. 检查桌面包确实没有 `skillshub-cli`，完成桌面签名、更新签名和已配置的公证。桌面公证与独立 CLI 公证分别验证。
6. 桌面发布任务必须等待 CLI 资源上传与可下载性验证成功后，才公开桌面安装包和自动更新清单。CLI 发布失败不能留下需要不可下载 CLI 的公开桌面版本。

桌面 Release 只保留安装包、自动更新归档、更新签名和 updater.json。独立 CLI 安装脚本更新为所选 CLI 资源仓库地址。

现有 `v0.11.0` 标签指向已打包旧提交，草稿文件亦为旧产物。实现完成后需单独决定该候选版本如何重新发布；不得直接公开旧草稿来宣称新设计已上线，也不得在本次实现中擅自改写已有标签。

## 主要文件范围

### Rust 后端

- `src-tauri/src/core/cli_distribution.rs`：新增固定平台资源解析与受校验下载。
- `src-tauri/src/core/tests/cli_distribution.rs`、`core/mod.rs`：下载回归测试和模块导出。
- `src-tauri/src/core/cli_bridge.rs` 及其测试：将状态和安装入口与内置二进制解耦，保留原子替换和目录保护。
- `src-tauri/src/core/network_proxy.rs`：按需补充受控 HTTPS 跳转配置与边界测试。
- `src-tauri/src/commands/mod.rs` 及其测试：用户点击触发下载、进度事件和既有启用流程。
- `src-tauri/src/lib.rs`：移除启动时的 CLI/官方 Skill 自动升级，保留状态可读性。
- `src-tauri/build.rs`、`tauri.conf.json`：只验证并嵌入小型 CLI 元数据，移除桌面包的 externalBin。

### 前端

- `src/components/skills/AiManagementSettings.tsx` 及其测试：阶段、进度、失败重试和版本待更新反馈。
- `src/components/skills/types.ts`：与后端同步进度和错误 DTO。
- `src/i18n/resources.ts`、`src/i18n/ko.ts`：提供英文、简体中文和韩文文案。
- 仅在现有样式无法承载进度反馈时修改 `src/App.css`，不调整页面整体布局。

### 构建、发布与记录

- `scripts/build-desktop.mjs`、`prepare-cli-sidecar.mjs` 及其测试：分离开发本地产物、CLI 发布产物和桌面元数据准备。
- 新增发布清单生成与验证脚本及测试。
- `.github/workflows/release.yml`、`ci.yml` 与工作流测试：CLI 和桌面分别准备资源，验证发布依赖和桌面包不携带 CLI。
- `scripts/install-cli.sh`、`install-cli.ps1` 及其测试：独立 CLI 下载地址。
- 中英文 README、CHANGELOG 和 `docs/releases/v0.11.0/`：更新按需安装、离线条件、更新操作和资源发布说明。

不迁移数据库，不修改技能安装、同步或撤销业务，不修改用户的真实目录作为测试手段。

## 验证与验收

- 测试先证明当前行为不满足新要求，再实现改变并验证通过。
- 用户首次启用仅下载当前平台和桌面版本；已验证的当前版本无需联网复用。
- 页面加载、切换设置和桌面启动不能下载、安装或读取凭据。
- 网络超时、404、错误长度、错误哈希及并发安装均不能覆盖已验证旧 CLI。
- HTTP 降级、异常跳转及代理继承被拒绝；运行 `npm run network:check`。
- 开发版不能使用正式版 CLI 冒充本地产物；测试不写真实 Agent 目录。
- CLI 更新与官方 Skill 更新保持顺序；失败不报告启用成功，目标部署与现有权限保护仍成立。
- 五平台 CLI 原生检查通过，桌面包内没有 CLI；公开前验证固定版本 CLI 下载可用。
- 运行 `npm run version:check` 和 `npm run check`，完成桌面开发版启动检查。
- 本机打包后给出与现有 0.11.0 包的实际体积对比，不提前承诺恢复到 0.10.1 的大小。

## 进入实现前的审阅点

本设计需要确认两个产品选择：采用独立 CLI 资源仓库，以及将已启用 CLI 的版本更新改为用户点击触发。确认后再形成实现计划并开始代码改动。
