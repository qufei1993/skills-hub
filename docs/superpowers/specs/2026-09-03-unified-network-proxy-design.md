# Skills Hub 统一网络与代理架构设计

- 状态：已确认
- 日期：2026-09-03
- 目标版本：v0.10.0

## 背景

设备同步在推送较大仓库时曾长时间停留在“同步中”，最终只记录了 `push device sync repository`。排查发现，Skills Hub 设置页虽然已经提供“网络代理”，但各网络调用没有统一接入：部分功能读取该设置，设备同步、OAuth 和部分 libgit2 回退路径则各自创建客户端，因此可能绕过用户配置，也缺少一致的超时、回退和错误信息。

这不是单个调用点的问题，需要建立统一网络边界，保证现在和以后新增的联网功能都遵循同一套规则。

## 目标

1. Skills Hub 设置页的“网络代理”成为应用内所有网络请求的唯一配置来源。
2. GitHub、GitLab、Gitee 的 HTTP API、OAuth 和 Git clone/fetch/push 使用相同策略。
3. 已配置代理不可用时静默回退直连，不弹窗、不显示额外提示。
4. 所有网络操作具备合理的超时、取消和可诊断的错误链。
5. 通过代码边界和自动检查，阻止后续功能绕过统一模块。
6. 保持现有用户配置兼容，不要求重新配置代理。

## 非目标

- 不在本版本增加 PAC、远程代理账号管理或多代理规则。
- 不替代操作系统代理设置；浏览器中的 OAuth 授权页仍由浏览器自行决定网络路径。
- 不把代理地址、访问令牌、请求头或 OAuth 凭证同步到设备同步仓库。
- 不因代理回退改变认证错误、权限错误或业务错误的处理方式。

## 数据库降级兼容

设备同步只新增旧版本不会读取的独立表，不得因此提高共享主数据库的 `PRAGMA user_version`。主版本保持为 v0.9.1 可识别的 `6`，设备同步使用 `settings.schema.device_sync = 1` 独立记录自身 schema 版本。

曾被 v0.10.0 开发版写成主版本 `7` 的数据库，在启动时应幂等创建/校验设备同步表，然后自动恢复主版本 `6`；设备同步配置、历史、设备、冲突和回收站数据均保留。未来兼容性新增表或可忽略字段也遵循相同规则；真正不兼容的共享表变更必须先提供明确的降级方案，不能让旧版在启动回调中崩溃。

## 现状审计

| 网络场景 | 当前是否读取 Skills Hub 代理 | v0.10.0 处理 |
| --- | --- | --- |
| GitHub 仓库搜索 | 是 | 迁移到统一 HTTP 入口 |
| 推荐 Skills / skills.sh 搜索 | 是 | 迁移到统一 HTTP 入口 |
| Skill 安装与更新 | 部分 | Git CLI、HTTP 和 libgit2 全部迁移 |
| 版本说明与应用更新 | 是 | 通过更新适配器读取统一策略 |
| 设备同步仓库 clone/fetch/push | 否 | 迁移到统一 Git 入口 |
| GitHub/GitLab/Gitee 仓库查询与创建 | 否 | 迁移到统一 HTTP 入口 |
| OAuth 启动、轮询和刷新 | 否 | 迁移到统一 HTTP 入口 |
| 系统 Git 不可用时的 libgit2 回退 | 否 | 迁移到统一 Git 入口 |

## 总体架构

```text
Skills Hub 设置
  └─ NetworkPolicy（唯一配置与决策源）
       ├─ HttpTransport
       │    ├─ GitHub / GitLab / Gitee API
       │    ├─ OAuth 启动 / 轮询 / 刷新
       │    └─ 搜索 / 推荐 / 版本信息
       ├─ GitTransport
       │    ├─ 系统 Git
       │    └─ libgit2 回退
       └─ UpdaterAdapter
            └─ Tauri Updater

每个传输入口：超时 + 取消 + 代理优先 + 符合条件时静默直连回退 + 脱敏诊断
```

业务模块只描述“请求什么”，不再自行读取代理设置、环境变量、创建 `reqwest::Client`，也不直接为远程 Git 操作配置代理。

## 模块划分

后端统一模块位于：

```text
src-tauri/src/core/network/
├── mod.rs       # 对业务层公开的稳定入口
├── policy.rs    # 读取设置、兼容旧配置、选择网络路径
├── http.rs      # HTTP 客户端、重试、超时和取消
├── git.rs       # Git CLI/libgit2 适配、进度、超时和取消
└── error.rs     # 错误分类、错误链和脱敏
```

现有 `network_proxy.rs` 的能力迁入该目录，并保留过渡导出，避免一次性扩大无关改动。

前端不自行复制代理判断逻辑。Tauri Updater 无法直接复用 Rust HTTP 客户端，因此由 `UpdaterAdapter` 提供已经解析好的更新参数，并保持与 `NetworkPolicy` 相同的回退规则。

### NetworkPolicy

职责：

- 从应用设置读取代理是否启用及代理地址。
- 兼容现有 `github_proxy_url` 配置键；内部统一使用通用的 `network_proxy_url` 命名。
- 首次读取旧键时迁移到新键；迁移失败时继续使用旧值，不中断网络操作。
- 规范化并校验代理 URL，不接受凭证被写入日志。
- 生成一次请求所需的代理路径与直连回退策略。

设置优先级固定为：应用设置 > 无代理。业务模块不得再读取 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 或 Git 全局代理作为应用策略。底层工具执行时显式传入或清除相关代理参数，避免行为受启动环境偶然影响。

### HttpTransport

统一提供：

- 带连接超时和总超时的客户端。
- 代理与直连两种明确路由。
- 请求安全性分类：可重试读取、幂等写入、非幂等写入。
- 仅针对连接失败、代理隧道失败、DNS/传输中断等网络错误执行回退。
- 对 `401`、`403`、限流、参数错误及其他服务器业务响应不回退。
- 结构化、脱敏的完整错误链。

### GitTransport

统一承接 clone、fetch、push：

- 系统 Git 与 libgit2 使用相同的 `NetworkPolicy`。
- 记录连接、接收对象、写入对象、推送等阶段和已用时间。
- 支持取消；超过约定时间不再无限等待。
- 代理路径发生传输错误时，在确认操作可安全重试后直连一次。
- push 以目标提交和远端 ref 为依据判断是否已经成功，避免模糊失败后重复产生副作用。

### UpdaterAdapter

应用更新保留 Tauri Updater，但代理参数、超时和回退决定统一由适配器提供。这样前端没有第二套代理配置，也不会把凭证暴露给 UI。

## 代理路由与回退规则

```text
代理关闭
  └─ 直接连接

代理开启
  ├─ 本地代理端点预检失败 → 直接连接
  └─ 预检成功 → 使用代理
                    ├─ 成功 → 返回
                    ├─ 认证/权限/业务错误 → 原样返回，不回退
                    └─ 连接/隧道/传输错误 → 判断操作安全性
                                              ├─ 可安全重试 → 直连一次
                                              └─ 不可确认 → 先核对远端状态
```

回退最多发生一次，不形成代理与直连之间的循环。

“静默回退”仅表示不打扰用户。内部仍记录脱敏诊断，包括请求类型、平台、代理或直连路径、失败阶段和耗时；不得记录 Token、Authorization 请求头、OAuth code、refresh token、Cookie 或含凭证的 URL。

### 不同操作的安全性

| 操作 | 回退策略 |
| --- | --- |
| GET、仓库列表、OAuth 状态轮询 | 代理传输失败后可直连一次 |
| Git clone/fetch | 清理或复用安全临时目录后可直连一次 |
| Git push | 先查询远端 ref；未到达目标提交才直连重试 |
| 创建仓库 | 失败结果不明确时先按 owner/name 查询；不存在才重试 |
| OAuth token 交换/刷新 | 仅在确认请求未被服务端接受时重试；否则重新查询或让现有流程继续轮询 |

## 设备同步可靠性

统一代理模块同时解决此前同步长时间无反馈的问题：

1. 连接阶段默认 30 秒超时；网络传输连续 5 分钟无进展则中止。持续有进展的大仓库不会被总时长粗暴截断。
2. 前端显示当前阶段和耗时，并允许取消；不再只有无限期的“同步中”。
3. 失败时保存完整、脱敏的错误原因链，而不是只保存最外层上下文。
4. 使用作用域清理机制，成功、失败或取消都清除 `export-*` 临时目录。
5. 应用启动时将遗留的 `running` 记录恢复为“上次同步被中断”，避免永久运行状态。
6. 同步前统计文件数和体积；超大内容给出非阻塞说明，但不替用户删除 Skill。
7. 只有内容实际变化才创建 Git 提交；失败重试不会凭空增加版本。

## 防止未来绕过统一模块

### 静态架构检查

新增 `scripts/check-network-boundaries.mjs`，并接入 `npm run check`。生产代码出现以下情况时检查失败：

- 在 `src-tauri/src/core/network/` 之外直接创建 `reqwest::Client`。
- 在统一 Git 适配层之外配置远程 libgit2 callbacks/proxy 或执行联网 Git 命令。
- 业务模块直接读取代理环境变量或代理设置键。
- 前端在更新适配器之外自行读取、拼装代理配置。

测试代码和明确列入白名单的底层适配器不受此限制。白名单必须集中维护，并在代码评审中说明原因。

### 项目规则

在 `AGENTS.md` 增加以下约束：

> 所有新增出站 HTTP、OAuth、Git 和更新请求必须通过统一网络模块；代理配置只来自 Skills Hub 设置。联网操作必须定义超时、取消、错误脱敏及代理失败后的安全回退测试。业务模块不得直接创建网络客户端或读取代理环境变量。

这条规则与静态检查共同生效：规则指导实现，检查阻止遗漏。

## 错误处理与用户体验

- 代理自动回退成功：不提示用户。
- 代理和直连都失败：展示最终可行动的错误摘要，并保留两条路径的脱敏原因用于诊断。
- 认证或权限失败：明确提示重新授权或检查仓库权限，不伪装成网络问题。
- 同步过程中：展示阶段、耗时和取消操作。
- 同步历史：失败项显示可展开的错误详情；内部技术信息经脱敏后再展示。

## 测试策略

### 单元测试

- 代理关闭时只走直连。
- 代理开启且可用时优先走代理。
- 本地代理端点不可达时直接回退。
- 代理在传输中断开时，仅安全操作直连重试一次。
- `401`、`403`、限流和业务错误不触发回退。
- 日志和错误中不出现 Token、请求头或 URL 凭证。
- 旧代理配置键可无感读取与迁移。

### 集成测试

- GitHub、GitLab、Gitee 的仓库列表、创建仓库和认证验证。
- OAuth 启动、轮询、Token 交换和刷新。
- Git clone、fetch、push 的代理、回退、超时与取消。
- 系统 Git 不可用时的 libgit2 路径。
- 前台手动同步与后台自动同步使用相同策略。
- 大仓库传输停滞会在限定时间内失败，并清理临时目录。
- 模糊 push/create 失败时先核对远端状态，不重复执行副作用。
- 应用重启后恢复遗留的运行中记录。

### 架构回归测试

- 静态边界检查覆盖 Rust 与 TypeScript 生产代码。
- macOS、Windows、Linux 使用同一策略；平台差异只存在于底层执行适配器。
- `npm run check` 必须包含静态边界检查、前端测试和 Rust 测试。

## 实施顺序

1. 建立 `NetworkPolicy`、错误分类和脱敏能力，兼容现有代理设置。
2. 建立 `HttpTransport`，迁移设备同步 Provider API 与 OAuth。
3. 建立 `GitTransport`，迁移设备同步和 Skill 安装/更新的 Git 网络路径。
4. 接入更新适配器，并迁移其余已使用代理的调用，删除重复逻辑。
5. 加入同步超时、取消、进度、完整错误链和临时目录清理。
6. 加入静态架构检查和 `AGENTS.md` 规则。
7. 完成三平台、三代码托管平台及失败场景测试。

## 备选方案及取舍

### 只修设备同步

改动小，但搜索、OAuth、更新或未来功能仍可能再次遗漏代理，不能解决根因，因此不采用。

### 完全依赖系统代理或环境变量

实现简单，但与 Skills Hub 设置页不一致，不同启动方式和平台行为不可预测，因此不采用。

### 代理失败后始终直接重试

读取请求可行，但创建仓库、Token 交换等操作可能已经在服务端成功，盲目重试存在重复副作用，因此不采用。

## 验收标准

- v0.10.0 初始化或使用设备同步后，v0.9.1 仍可打开同一主数据库。
- 已被开发版标记为 schema 7 的数据库自动恢复兼容，设备同步数据不丢失。
- 用户只需在 Skills Hub 设置页配置一次代理，所有应用内网络功能立即遵循该配置。
- 代理不可用时，安全操作自动直连一次，界面不显示代理回退提示。
- GitHub、GitLab、Gitee 的 OAuth、API 和 Git 同步均通过统一入口。
- 网络停滞不会持续数小时；用户能看到阶段、耗时并取消。
- 同步失败不遗留大体积临时目录，历史记录包含可诊断且已脱敏的原因。
- 新代码绕过统一网络模块时，`npm run check` 会失败。
- 现有代理配置无需用户重新填写。
