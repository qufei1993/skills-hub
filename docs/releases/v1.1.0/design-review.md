| R08 | P1 | 多选保存替换原批量操作，并插在列表上方 | 复用底部批量栏，只增加保存预设，不抹去已有批量能力 |
| R09 | P1 | 详情丢失状态、工具、标签、来源、文件数的原层级 | 保留原 metadata rail 和文件浏览主体，仅增加使用位置与所属预设 |
| R10 | P1 | 选择器依赖滚动查看所有成员，规模稍大就难用 | 搜索、仅已选、当前结果批选；用 50 预设／500 Skills／20 项目测试 |

P0 是会误导作用范围、产生意外部署或让核心任务不可达的问题。P1 是阻碍常用任务、规模使用或与现有产品融合的问题。未完成验证前不把这些条目标成已解决。

## 新信息架构与页面职责

| 页面 | 回答的主要问题 | 最常用动作 |
| --- | --- | --- |
| 我的 Skills | 我有哪些 Skills，具体部署在哪里？ | 筛选项目、添加已有 Skills、管理当前项目目标 |
| 技能预设列表 | 哪套配置适合这次工作？ | 查找、查看、应用、新建 |
| 预设详情 | 这套配置包含什么、给哪些工具使用、以前应用过哪里？ | 应用到目标、编辑、查看历史 |
| 预设编辑 | 我要保存哪些成员和工具分配？ | 搜索选择、调整分配、保存／取消 |
| 应用选择 | 本次要改哪些位置？ | 选择全局或一个／多个项目，确认工具规则 |
| 应用预览 | 每个目标将新增、跳过、修复或保留什么？ | 按项目检查实际计划、明确提交 |
| 应用结果与全部记录 | 什么已完成，什么还需要处理？ | 失败续作、查看项目、安全撤销本次新增 |
| 更新 | 计划如何运行，本次结果如何，哪些内容需要比较或恢复？ | 沿原调度及结果布局查看差异、恢复指定 Skill |
| Skill 详情 | 这份内容是什么、被哪里使用？ | 浏览文件、查看使用位置、返回来源页 |

工作区顺序为“我的 Skills → 添加 Skills → 技能预设”。“所有项目”仍是我的 Skills 中的筛选值，按 Skill 去重，不增加同质总览页。全部应用记录是技能预设页的独立页签，不再增加一个一级历史模块。

## 核心任务验收

完整任务是：从已经用好的项目准确保存成员与工具关系，在一个入口应用到多个明确项目，检查逐项目变化，遇到失败继续剩余项，后续仍能找回记录并安全撤销。

按以下行为验证：

1. 复用准确：保存当前项目不意外扩张工具范围。
2. 跨页连续：从项目进入、挑选预设、预览、执行、返回项目，用户不丢上下文。
3. 恢复可找到：历史不会因记录变多或模板删除而消失，多个 Skills 更新互不覆盖恢复入口。
4. 重叠操作可预测：撤销只处理仍属于本次、未被后续使用或修改的新增目标。

这些是设计目标与可验证行为，实际效果需要真实后台及用户任务测试。

## 验证门槛

### 信息架构与融合

- 任意主页面一次点击到技能预设，无需先打开弹窗。
- 真实截图与源码对照：主列表／底部批量栏、更新计划／结果、详情 metadata／文件树均保留原布局职责。
- 评审说明默认收起，产品区有足够空间；新增标注可打开查看。
- 标题、主操作、返回位置一致，危险操作的作用范围在点击前可辨识。

### 交互及数据

- 预设 CRUD 不部署；保存准确工具映射；编辑不自动改过去项目。
- 全局与项目目标独立；项目共用目录规则不套到全局。
- 多项目应用按项目计划及反馈，失败不拖回成功项目，重试不重复写入。
- 第 20 条及更早记录可找回；模板删除不删历史。
- 搜索预设、成员、项目，筛选已选，长名字和空态可用。
- A/B 重叠、后续手动使用、目标换代和内容变更都受撤销保护。
- 项目移除不改全局、其他项目或中央资产。
- react 与 ui 两份内容分别更新后，两份恢复记录都可用；过期预览停止写入。

### 视觉与键盘

- 检查 1440、1280、1024、768 和 390px 宽度；产品主体优先验证桌面尺寸。
- 检查顶部信息密度、首屏主操作、表头对齐、长路径换行、横向溢出、底部操作栏遮挡和弹窗裁切。
- 键盘可到主要动作，原生表单有标签，焦点可见；短确认弹窗可取消并返回。
- 空态、零结果、部分成功、冲突、后续修改、未保存编辑离开均有明确行为。

已完成重新设计、独立复核及修正后的再次验收。R01–R12 在本次原型检查范围内全部关闭；未发现剩余 P0／P1。该结论限于模拟交互与页面设计，不代表生产后台或真实用户任务验收已经通过。

### 实际验收证据

- **独立交互验收 20／20 通过**，包含 50 个预设、500 个 Skills、20 个项目和 25 条历史记录。验证的是搜索、分页、状态和流程，不将 JSDOM 执行时间当作生产性能。
- **工作区回归 8／8、导航与键盘回归 4／4 通过**。共运行 32 组检查，部分场景有交叉复核。
- **浏览器布局矩阵 40 个组合通过**：1440／1280／1024／768／390px，各检查我的 Skills、预设列表、全部记录、预设详情、编辑、应用选择、更新和 Skill 详情。未检测到页面横向溢出或无标签的可见表单。另逐步检查了应用预览、结果、局部移除和短确认弹窗。
- 实际查看桌面和窄窗口截图；最终 390px 应用预览完整显示处理列。详情保留文件树与 metadata，更新保留计划和执行结果，底部批量栏保留原能力。
- 真正的浏览器按键验证 Space／Tab 连续选择；应用结果 → 项目 Skills → 原结果链路验证通过。最终浏览器控制台无错误或警告。
- 设计 lint 无 FAIL；等宽路径、弹层和原有底部操作栏等 WARN 已按产品上下文核对，未为通过通用检查而偏离原有品牌。
- 仓库 HTML 与当前 4178 服务目录 HTML 逐字节相同。没有改动生产 `src`、已有运行服务或无关的用户修改。

可重跑的检查在 `work/prototypes/review/`：`review-independent.cjs`、`check-workspace.cjs`、`check-final-navigation.cjs`。保存了 `interaction-results.json` 与 `browser-layout-results.json`。在仓库根目录执行对应 `node work/prototypes/review/<文件名>`；需要现有项目的 jsdom 依赖。
