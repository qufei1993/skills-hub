# Skills Hub 1.1.0：项目、技能预设与可恢复操作

> 研发参考基线：v1.1.0-design-r1 · 2026-10-24。与本目录原型和交接说明配套，下一轮设计不覆盖此文件。

评审日期：2026-10-23。依据当前生产代码、现有页面结构及用户任务。此次纳入技能预设（Preset），并经全面评审改为常驻页面，完成复用、应用和恢复的闭环。详细问题、页面依据与复核门槛见 [全面设计评审](design-review.md)。交互原型使用模拟数据，不能视为生产功能已经实现。

## 本次决定

保留原有 UI、列表与管理中心结构，在工作区增加常驻“技能预设”页面；“我的 Skills”增加具体项目管理与快捷复用入口；更新沿现有计划控制和执行结果布局增加影响预览与恢复。

Preset 的用户名称为“技能预设”：保存一组经常一起使用的 Skills，可应用到全局或具体项目。预设定义和应用记录分开，浏览、创建、编辑、复制、删除预设均不改变现有部署；明确执行“应用到……”才修改目标。它不局限于项目，也不要求用户为每个项目先建方案。

预设用于重复配置需求。本次不引入隐式切换、自动卸载、互斥的活动配置，也不提供在线分享。

## 设计依据与文档范围

设计围绕现有用户任务展开：保存已验证的成员与工具分配，在明确目标中重复使用，检查实际变化，处理失败，并找到可恢复的操作记录。页面沿用当前产品结构，功能按任务完成情况验收。

仓库内设计材料仅记录本产品的需求、行为、实现约束和验收结果。外部产品调研的名称、仓库链接、提交标识和比较分析保存在仓库外，不放入待提交的设计文档、原型或评审附件。

## A：具体项目与明确目标

- 保留“全部／全局／项目”。项目默认“所有项目”，按 Skill 去重；“全部”还包含只有全局部署的 Skills。不新增一个重复总览页。
- 选择项目仅改变视图。允许选择还没有部署的新目录；选择目录不写入 Skills。
- 同一中央 Skill 可以同时有全局及多个项目目标。不能把范围设计成互斥的资产分类，或要求用户重复导入内容。
- 具体项目卡片展示该项目目标，主操作为管理本项目目标，支持明确预览后的局部移除。资产级停用、从技能库删除移至明确的资产上下文，不能继续在项目卡片放一个看似局部的开关。
- 手动添加与预设应用共用全页面流程：选择成员与目标 → 检查计划并确认 → 执行结果。具体项目入口已确定范围且工具映射完整时可直接进入预览，仍可返回调整。未选项不代表删除。
- 具体项目或全局页面预填当前范围；“全部／所有项目”必须明确选择目标。项目模式支持一次选择多个项目，各项目分别生成计划和结果；全局与项目分开，不默默应用到全局。
- 已停用的 Skill 需明确处理启用意图，不能因应用预设而隐式恢复其他目标。
- 全局记录不自动算作某项目的有效部署。只按经验证的工具规则解释继承和覆盖；添加项目目标不删除全局目标。
- Codex／Cursor 的项目 `.agents/skills` 为本原型的共享目录示例，预览展示共同影响。全局目录不能沿用这个合并规则。
- 已有健康目标跳过；缺失部署可以修复；同名不同内容保留并标为冲突，不强行覆盖。失败后保留成功项，重试未完成项。

实现 A 必须调整现有范围分类、工具操作和目标生命周期。数据库已有多个目标的表达基础，但 `getSkillScope` 的互斥分类及 `handleScopeChange` 的迁移语义不满足上述行为，不能当作只加一个筛选器。

## D：技能预设（Preset）完整流程

### 创建与管理

工作区常驻入口顺序为“我的 Skills → 添加 Skills → 技能预设”。预设主页面有“预设／全部应用记录”页签；列表支持按名称或成员搜索，展示用途、成员／工具摘要和最近应用；不为每个预设增加侧栏子项。

详情页面展示名称、用途、成员及逐成员工具分配、应用记录，顶部主操作为“应用到…”。编辑、复制、删除是次操作。成员可进入已有 Skill 详情并返回原预设；页面返回保留搜索、筛选及项目上下文。删除和放弃未保存编辑可用短确认弹窗，不把整套长期管理装进弹窗。

创建入口包括：原 Skills 底部批量栏增加“保存为预设”、具体项目“保存当前配置”、预设页“新建”。保留原批量标签／工具／更新／启停／删除能力。名称必填且不重复，至少一个成员；描述可选。成员选择支持搜索、仅已选及批选当前结果，不依赖遍历全部技能。

预设保存成员标识和成员对应工具，不绑定本机绝对项目路径，也不保存独立内容版本。从当前项目创建必须准确保留成员→工具映射：原来仅 Codex/Cursor 使用的 Skill，不得由于其他成员使用 Claude 就默认给它也加上 Claude。共同默认工具是便利输入，不能替代异构分配。

### 应用与覆盖

应用默认使用预设工具分配；只有明确选择“统一指定工具”时才为本次选择改用共同工具。缺少工具选择时提示补充。项目共享目录按已验证规则展示共同影响，全局工具保持独立。

项目范围可选一个或多个项目，清楚显示名称、完整路径与所选数量。预览按项目汇总新增、已有、修复和冲突，再展开逐项明细；主数量先用“Skills／工具／项目”，需要时解释工具目标和共享目录写入数。执行结果按目标区分，成功项保留、失败项续作，冲突不覆盖。

覆盖状态依赖当前目标与现有成员，不能给模板一个脱离位置的“已开启”状态。从项目快捷入口继承范围；通用预设列表不反复显示无意义的“请选择范围”。旧应用记录可按最新定义重新检查缺项，但不将历史快照伪装为实时绑定。

原型中的失败和冲突明确为模拟场景；生产计划来自实时检查。已停用／已移除成员必须解释阻止原因，不隐式启用，不以静默跳过伪报完整成功。

### 编辑、删除与历史

编辑只保存定义，已应用项目不变。新增成员可再次应用补齐；移出成员不会自动卸载，保存时说明。删除模板不删除中央内容、部署和应用记录。

全部应用记录保存手动添加和预设应用，搜索／筛选后能访问所有历史，不能只显示最近 8 条而让旧结果失联。每条保留当时名称、成员和工具／目标快照；模板改名、编辑、删除不改写历史。一次批量应用可以按目标保存记录并关联同一批次，按项目查看结果和恢复。

结果提供“查看目标项目”“返回预设／来源”等明确去向，不强制跳到另一个无关列表。取消编辑或应用返回原上下文，未经确认不产生部署。

### 撤销本次新增

应用结果和记录提供“撤销本次新增”，先预览实际可撤销范围。

| 当前情况 | 撤销行为 |
| --- | --- |
| 此次新建、内容和目标仍与写入时一致，后续没有被明确复用 | 可以撤销该目标。 |
| 应用前已存在的目标 | 保留；不是本次新增。 |
| 本次仅修复的已有目标 | 保留，不把修复后的目标卸载。 |
| 后来的预设或手动应用再次选择了这个目标 | 保留，并说明后来操作仍使用它。 |
| 内容／目标后来被修改，或归属无法可靠判断 | 保留并说明，不以“恢复成功”掩盖跳过。 |
| 共享物理目录仍被其他工具目标引用 | 保留必要目录，不能仅按一条逻辑目标记录删文件。 |

这是操作级恢复，不是将项目回退到旧快照。撤销不得删除中央库资产或覆盖应用之后的个人修改。首版不承诺自动计算跨多次撤销的最小剩余集合；遇到来源不明确时保留并提供明确结果。

## B：更新差异与内容恢复

沿 `UpdatesPage` 原有计划控制卡和执行结果卡增加功能：保留启停、时间方式与立即执行，待更新行打开差异；对应成功结果进入该 Skill 恢复。无执行时不展示虚构统计，执行计数从结果逐项汇总。

更新前显示文件新增、修改、移除及具体差异，明确中央内容和所有目标的影响。确认执行时重新检查内容、来源基线与目标是否变化；过期预览不得直接执行。

实际写入前保存恢复内容及必要元数据。手动、批量、自动、CLI 更新应复用同一底层保护；自动更新沿用既有授权，不增加每次弹窗。

首版为每个 Skill 独立保留最近一次成功更新后的“恢复更新前内容”，不建设任意版本历史。连续更新两个 Skills 不得覆盖彼此的恢复机会。恢复前检查后续内容修改；如有新编辑，停止覆盖。只恢复内容和对应版本元数据，不恢复整个项目配置，不撤销后来新增的部署或应用记录。

恢复后同一上游新版等待手动重新更新，避免下一次自动检查立即覆盖用户恢复。来源版本与基线须同步处理，不能只改显示版本号。

## C：就地处理问题

部署缺失显示位置、原因及将修复的目标；来源失效允许重新绑定并预览。修复保留中央内容、原身份及无关目标，不把导入另一份同名内容当修复。不增加来源收藏中心、健康仪表盘或日常无事也需要处理的提醒。

## 数据与实施边界

建议共同领域服务分别处理：

1. 预设定义：名称、描述、成员及逐成员工具映射；可移植，不含本机路径。
2. 应用计划：明确范围、工具、目标标识、预览依据与逐项动作；GUI 和 CLI 共用。
3. 应用记录：当时预设快照、请求目标、实际复用目标、本次新增及写入状态、失败结果、撤销结果。
4. 内容恢复记录：每个 Skill 的最近一次更新前内容及版本基线、更新后指纹；与部署撤销分开。

已有设备同步可以承载未来的预设定义，但当前 manifest 没有这项内容，必须扩展才可宣称支持。应用目标中的本机项目路径不直接跨设备复制。已有 AI CLI 复用共同预览／执行服务，原型没有实现这项后台接入。

生产实施顺序：先补多目标范围与可靠计划执行，再增加预设及应用记录，随后接入更新恢复与现有同步／CLI；UI 原型可同时展示四项，以便评审完整体验。

明确不做：在线分享、预设继承与优先级、方案版本选择器、切项目时自动停启全局 Skills、持续自动跟随、自动清理预设之外的内容、新聊天窗口。以上均不是完成当前闭环的前提。

## 用户任务验收目标

下面是建议验收目标，尚未完成真实用户任务测试，不能作为已达成的宣传数字。

| 真实任务 | 验收目标 |
| --- | --- |
| 将已经用过的 10 个 Skills、2 个工具复用到新项目 | 内容已有或缓存可用时，中位完成时间 ≤60 秒；不重新逐项选择；相对目前手工流程减少至少一半时间；重复应用零重复写入。 |
| 调整预设后只补齐项目 A，保留项目 B 和手动添加项 | 预览与执行逐项一致，未选范围零写入；至少 90% 试用者能准确说出影响范围。被移出预设的旧成员明确保留，不伪称自动跟随。 |
| 部分失败后补齐，随后撤销且期间有新修改 | 无冲突恢复中位 ≤60 秒；不丢后续修改、不撤无关目标；冲突和保留项如实显示，GUI／CLI 最终使用相同计划。 |

原型验收包括：创建／浏览／编辑／删除的纯定义操作、全局与项目应用、空项目、重复零新增、部分失败重试、A/B 重叠保护、模板删除后历史仍可撤销、后续修改保护、全局与项目共享目录边界、更新内容恢复不影响后续目标，以及不同窗口尺寸的布局。

当前交付为本地 HTML 交互原型和此设计说明；所有实际文件系统写入、持久存储、设备同步及 CLI 接入都属于后续生产开发。

## 验证状态

新的常驻工作区已通过独立交互 20 组、工作区回归 8 组、导航及键盘 4 组检查，并完成 5 种宽度 × 8 类页面的浏览器布局核查。评审发现的返回链、范围文案、窄屏计划列和焦点丢失已修复并复核；当前检查范围内无未解决 P0／P1。具体证据及原型与生产的边界见 [全面设计评审](design-review.md)。
