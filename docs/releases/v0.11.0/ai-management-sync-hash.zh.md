# 设备同步后的 AI 一键管理修复

[English](ai-management-sync-hash.md) · [发布总览](README.zh.md)

设备同步原先把跨设备清单校验值写进了本机 Skill 的目录校验字段。两者计算方式不同，文件没有改动也可能被判定为已修改，导致 AI 管理预检查失败，尚未进入 CLI 安装。显示相同的 Skill 版本不能证明文件校验通过。

设备同步现在写入暂存目录的本机校验值。用户主动启用 AI 管理或更新官方 Skill 时，仅在旧跨设备校验值与当前文档及元数据一致时恢复错误记录。恢复要求来源为官方内置 Skill、中央路径为普通目录、目录中只有普通 `SKILL.md`，且文件权限正常。真实内容修改、额外文件或目录、链接、未知校验值和异常权限仍被拦截。原有 ID、创建时间、标签和部署范围得到保留。

查看状态和预检查不会改写记录。启用或更新成功时，通过现有写锁和目录替换保护提交正确的本机校验值，无需数据库结构升级。启动应用不会自动安装或更新 AI 管理。

CLI 仍严格校验大小和摘要。以前开发环境或旧构建安装的 CLI，即使版本号相同，也可能与当前应用要求不同；一键启用负责安装匹配的 CLI，状态提示改为引导此操作。草稿 Release 的公开 CLI 下载地址不可用，草稿阶段可通过项目提供的本地测试构建验证，不能为了测试而直接公开版本。

## 验证

回归测试在修复前复现了原始同步校验错误。覆盖同步后启用、旧记录安全恢复且预检查不写入、旧版官方 Skill 更新、标签和数据库兼容性保留、真实修改与不安全文件结构拦截，部署失败回滚，以及 CLI 下载失败时不修改 Skill。最终 `npm run check` 全部通过：290 项前端测试、636 项 Rust 单元测试、2 项兼容性测试、19 项 CLI 集成测试，以及网络边界、代码检查、构建、格式和 Clippy 检查。`npm run tauri:dev` 已从修复分支构建并正常启动。原生窗口检查选中了原有正式版应用，不能据此声称开发窗口已完成视觉验证；没有在真实技能库中执行测试启用。

此前的 0.11.0 草稿安装包不包含本次修复，需在确认修复提交后重新构建并完成发布验证。发布保持草稿，等待发布负责人确认后再公开。
