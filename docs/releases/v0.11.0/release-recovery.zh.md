# 发布恢复验证

CLI 替换失败时保留原有有效二进制及版本、校验记录。恢复时先在受保护目录中核对旧哈希，再判断是否需要替换二进制。macOS 文件不可修改标志与 Windows 禁止删除共享的句柄回归覆盖替换本身被拒绝的情况。反复配置正式版、开发版终端后，新 Bash 或 Windows cmd 应选择当前指定的 CLI，并保留其他配置内容。

桥接发布与状态读取在关闭文件描述符前显式释放独占锁或共享锁。close-on-exec 继续阻止 exec 后继承描述符；显式解锁还避免并发 fork 的子进程在 exec 前的短暂窗口内继续持有已结束操作的锁。回归通过管道握手让真实子进程停在 exec 前，验证发布成功、失败回滚与共享锁释放，不依赖等待时长或串行执行测试。

一键启用也可在已记录的中央库位置重建丢失的受管理官方 Skill 目录，保留 Skill ID 并恢复原有部署。状态读取与预览不会创建目录；部署失败时恢复原来的目录缺失状态和数据库记录。不安全路径、符号链接、冲突目标及并发新建目录仍受到保护。官方内置 Skill 在各平台检出时统一使用 LF 换行，frontmatter 回归同时接受 LF 与 CRLF。

五个平台均在桌面打包前执行 CLI 桥接、终端和官方 Skill 服务的恢复回归。Linux 最低要求 glibc 2.39（Ubuntu 24.04 或兼容环境）。Linux 检查读取实际 deb 元数据，安装含候选程序内容的临时前序版本，再升级到未经修改的候选包，核对登记版本、文件归属并启动已安装的 deb 和提取的 AppImage。此项验证包替换，不代表旧稳定版数据迁移或应用内在线升级测试。

CLI 资源准备脚本只允许草稿，在任何远端操作前拒绝 `--publish`。最终版本在发布者明确授权前保持草稿。草稿资源字节、更新签名和下载地址的核对，不能表述为匿名自动下载已成功；公开下载地址在草稿状态仍不可访问。
