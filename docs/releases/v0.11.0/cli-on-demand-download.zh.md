# CLI 按需下载验证

桌面安装包不再携带 CLI。在设置中点击启用或更新 AI 管理后，下载桌面要求的固定版本与平台文件，以内嵌的长度和 SHA-256 校验，再通过现有受保护目录与原子替换流程安装。已校验的对应版本可离线复用；启动和状态查询不更新 CLI 或官方 Skill。

## 构建约束

CLI 使用非默认的 Cargo `cli` feature，由 CLI 准备脚本及完整 Rust 测试启用；桌面打包不启用它。打包工具升级到 Tauri CLI 2.12.0，因为原锁定的 2.9.6 会在二进制发现阶段重新加入被禁用的次要程序。每次打包先清理生成目录，完成后检查实物。

## 远端状态与发布前置条件

先前新建的 CLI 仓库已停止使用，尚未删除。CLI 文件改为与桌面文件存放在原仓库同一个 Release 中。现有桌面 v0.11.0 仍为草稿，标签未改写。

五平台原生验证、Windows PowerShell 测试、已配置的平台签名与公证、发布资源完整性仍需在 CI 验证通过后才能公开版本；公开后还要验证真实匿名下载。本机结果不能替代这些检查。发布负责人需要先确定包含本次改动的候选版本和标签；旧草稿不能作为本实现直接公开。

## 最终审查与实现决定

最终审查发现的 Windows 门禁、默认构建目录和必需清单说明已在一次修复中完成。Windows 现在检查 `release/nsis/x64/installer.nsi`，缺失或包含 CLI 时失败；默认打包显式传递平台目标。回归测试先失败再通过，最终完整检查通过：282 项前端测试、623 项 Rust 单元测试、2 项兼容测试及 19 项 CLI 集成测试。工作流与版本检查通过。没有再次发起独立审查；没有遗留本次审查的小问题。

执行中的全部裁定与代价记录如下：

1. 继续使用本会话已批准的专用分支，保留已有设计与计划；代价是当前工作目录承载该功能改动。
2. 复用服务层 dry-run 做前置检查，避免重复冲突逻辑；如果范围判断不正确，需要调整 dry-run 语义。
3. 增加资源发布与实物包检查脚本，核对公开前的资源和桌面文件；代价是增加脚本维护。
4. 先提交再实物打包和审查，保证来源提交可核对；代价是验证记录需要后续提交。
5. 打包前清理生成目录，避免旧产物干扰；代价是重新生成打包输出，保留编译文件。清理本身不能解决 CLI 自动进入包的问题。

7. 升级 Tauri 构建工具至 2.12.0，修复旧工具重新发现禁用二进制的问题；代价是构建工具变化，需要完整检查与实物验证。

## 发布位置修正

按用户澄清，CLI 与桌面安装包共用原仓库同一个 Release，按需下载及桌面体积优化不变。CLI 先暂存至草稿并核对摘要；桌面文件上传同一草稿后，再核对 CLI 并显式公开完整版本，最后验证匿名下载。草稿重试只补缺少的 CLI，拒绝同名不同字节，不向已公开且缺少 CLI 的旧版本补传文件。已创建的空仓库停止使用，未经明确删除授权保留。

本次修正的回归测试先失败再通过；最终 `npm run check` 通过（285 项前端、623 项 Rust 单元、2 项兼容、19 项 CLI 集成）。网络边界、版本与工作流检查通过。

## PR #169 CI 超时修正

CI 的 Cargo 元数据测试超过默认 5 秒，与 PR #168 的设备同步凭据恢复测试等待问题不同。使用真实 Cargo 加 6 秒启动延迟复现了原错误，修正后同一场景通过。元数据读取改为 offline/locked，并限制子进程 20 秒；仅此 Vitest 测试允许 30 秒，不增加全局测试超时。空 Cargo 缓存下的离线元数据读取也通过。合并最新 main 后，本地开发 CLI 清单需要重新准备，以匹配合并后的提交。

合并后的最终 `npm run check` 通过：290 项前端测试、629 项 Rust 单元测试、2 项兼容测试、19 项 CLI 集成测试。
