# Skill 更新中断恢复

修复 [#183](https://github.com/qufei1993/skills-hub/issues/183)。

更新进程被终止后，数据库可能一直保留 `running`，导致重启应用后仍无法点击“立即更新”。Windows 原先只检查计划任务是否已注册；运行状态轮询也绕过了旧的 macOS 显示修正。

配置读取和运行状态轮询现在都通过共享的跨进程操作锁恢复中断状态。保留 60 秒启动宽限期，之后确认没有持锁执行者时，以一个数据库事务记录“已停止”。已完成结果保持不变，中断项移回待处理列表。仍在持锁的长时间更新不会被误判，锁读取失败也不会被当作任务已停止。定期轮询不启动系统调度器进程。

手动触发同样受写锁保护，并在启动后台进程前释放锁。启动失败会结束对应状态，避免覆盖其他活动任务。不变更数据库结构、凭据或版本号。

回归测试会真正终止持锁子进程，验证重开数据库及后续轮询的恢复结果，并验证“立即更新”按钮重新可用。Windows CI 会原生执行自动更新回归测试。
