# Release recovery verification

CLI bridge replacement failures preserve the previous verified binary and version/checksum stamps. Recovery compares the current guarded file with the saved previous hash before deciding whether the binary must be replaced. macOS immutable-file and Windows deny-delete-handle regressions exercise refusal of the replacement itself. Repeated production/development terminal configuration restores the selected CLI priority in a newly started Bash or Windows cmd, preserving other profile or PATH contents.

All five native runners execute the CLI bridge, terminal and official Skill service recovery suites before desktop packaging. Linux installers require glibc 2.39 (Ubuntu 24.04 or a compatible environment). The Linux gate validates actual deb metadata, installs a temporary predecessor package containing the candidate payload, upgrades it to the unmodified candidate, checks its registered version and file ownership, and launches both installed deb and extracted AppImage applications. This tests package replacement, not a previous-stable data migration or an application-internal online update.

The CLI resource staging helper accepts drafts only and rejects `--publish` before any remote operation. Final releases remain drafts until the owner explicitly authorizes publication. Draft asset verification, updater signatures and direct resource metadata do not establish that anonymous automatic downloads have succeeded; those URLs remain inaccessible while the release is a draft.
