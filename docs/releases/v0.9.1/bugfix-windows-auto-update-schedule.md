# v0.9.1 Windows 自动更新计划修复

## 问题

Windows 11 用户启用 Skills 系统定时更新时，任务注册失败，并显示 `schtasks /Create` 的 `/MO` 参数无效。该问题由 [Issue #102](https://github.com/qufei1993/skills-hub/issues/102) 报告。

## 根因

Skills Hub 默认每 24 小时执行一次自动更新。Windows 任务计划创建逻辑把所有小时单位都直接转换为 `HOURLY /MO <小时数>`，因此默认配置会生成 `HOURLY /MO 24`。

Windows 的小时计划只接受 1 至 23 的修饰值；24 小时及更长间隔必须使用其他计划类型。分钟计划同样存在独立的修饰值上限，原逻辑没有在生成命令前处理这些平台约束。

## 修复

- 1 至 23 小时间隔继续使用 `HOURLY /MO <小时数>`。
- 最多 1439 分钟的间隔继续使用 `MINUTE /MO <分钟数>`。
- 24 小时、48 小时及其他整天间隔转换为 `DAILY /MO <天数>`。
- 无法通过 `schtasks` 精确表达的非整天长间隔会在任务创建前返回明确错误，不再执行必然失败的命令。
- Windows 命令参数生成现在返回可验证的结果，并覆盖相关边界条件。

## 验收

1. 默认 24 小时间隔生成 `DAILY /MO 1`，不再生成 `HOURLY /MO 24`。
2. 23 小时间隔仍生成合法的小时计划。
3. 48 小时和 30 天间隔分别生成 `DAILY /MO 2` 与 `DAILY /MO 30`。
4. 25 小时等非整天长间隔在执行 `schtasks` 前返回明确错误。
5. Windows 调度参数回归测试及完整 `npm run check` 全部通过。
