# v0.9.1 Windows 目录联接与已有 Skill 导入修复

## 问题

Windows 用户通过目录联接同步 Skill 后，停用、取消单个工具同步或删除 Skill 会出现“拒绝访问（os error 5）”，导致工具目录中的同步入口无法清理。

发现流程还会把工具目录中的历史副本识别为待导入 Skill；如果中央存储已经存在同名且内容完全相同的托管 Skill，导入仍会直接报“已存在”，无法继续接管这些副本。

这两个问题由贡献者 [@shadapang](https://github.com/shadapang) 在 Windows 11 上复现、分析并通过 [PR #110](https://github.com/qufei1993/skills-hub/pull/110) 提交修复。感谢其提供详细的系统行为验证和实际使用反馈。

## 根因

- Rust 在 Windows 上会把目录联接识别为符号链接类型，但 `remove_file` 对目录型 reparse point 调用 `DeleteFileW` 时会返回拒绝访问；目录联接需要通过 `remove_dir` 对应的 `RemoveDirectoryW` 移除。
- 命令层和同步引擎各自存在路径清理入口，仅修改其中一处无法覆盖停用、取消同步和删除等全部流程。
- 通用本地安装逻辑在中央目标目录存在时无条件报错，没有区分普通重复安装与发现流程接管相同内容副本的场景。

## 修复

- Windows 上清理符号链接类型路径时先尝试 `remove_dir`，失败后再使用 `remove_file` 处理普通文件符号链接。
- 命令层使用 `symlink_metadata` 检查路径，使目标已不存在的悬空链接也能被清理，并在错误中包含具体路径。
- 覆盖同步统一使用安全的路径清理逻辑，避免对目录联接执行递归删除。
- 为发现导入增加专用逻辑：只有中央路径对应已有托管记录且源目录与中央目录内容哈希一致时才复用该记录。
- 普通本地重复安装和内容不一致的发现副本继续报错，避免扩大安装接口的既有语义。

## 验收

1. Windows 目录联接可以从命令层和覆盖同步流程中移除，真实目标目录及其内容保持不变。
2. 停用、取消同步和删除 Skill 不再因目录联接返回拒绝访问。
3. 内容完全相同的历史副本可以通过发现流程复用已有托管记录。
4. 内容不同的同名副本仍被拒绝，普通本地重复安装行为保持不变。
5. 中英文 v0.9.1 更新日志已同步，`npm run check` 全部通过。
