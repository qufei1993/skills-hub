# v0.10.0 Skills 存储路径与移除安全修复

## 问题

用户修改 **Skills 存储路径**，或调整自定义工具的 Skills 目录时，如果所选目录与工具同步目录、本地原始 Skill 目录或当前存储目录重叠，后续迁移和清理可能把真实目录误认为应用创建的同步副本。

典型场景是先从 `~/Downloads/.../source/demo-skill` 导入本地 Skill，再把 Skills Hub 的存储位置或自定义工具目录改到与该源目录重叠的位置。旧逻辑在覆盖同步或清理旧目标时可能直接删除整个目录，用户也无法从系统回收站恢复。

该问题由 [Issue #123](https://github.com/qufei1993/skills-hub/issues/123) 报告，对应修复见 [PR #125](https://github.com/qufei1993/skills-hub/pull/125)。

## 产品边界

- **Skills 存储路径**由 Skills Hub 管理，用于保存托管副本，不应指向任何 AI 编程工具的 Skills 目录。
- 通过“本地目录”导入的原始 Skill 仍归用户所有。Skills Hub 只管理导入后的托管副本和同步目标，不删除本地原始目录。
- 修改自定义工具目录时，可以清理 Skills Hub 创建的旧同步副本，但不能删除本地原始目录或 Hub 托管源目录。
- 用户主动移除或无法确认归属的真实文件和目录进入系统回收站；自动更新不应产生系统回收站记录。能够通过路径记录和内容指纹确认的应用托管副本，在自动更新时使用应用内部的可回滚原子替换。
- 符号链接和 Windows 目录联接只移除链接本身。

## 根因

- 存储路径修改前没有统一校验新目录是否与当前存储目录、工具同步目录或本地原始目录重叠。
- 同步引擎允许源目录与目标目录相同或互相包含，覆盖模式可能先删除目标，再重新创建同步内容。
- 清理逻辑没有完整区分符号链接、应用创建的真实副本和用户的本地原始目录。
- 存储迁移逐项修改文件和数据库记录，失败时缺少统一的回滚边界。
- 自定义工具目录冲突直接显示后端英文错误和完整路径，没有说明保存是否生效及用户下一步应该做什么。

## 修复

- 修改 Skills 存储路径前执行统一预检，拒绝以下情况：
  - 新旧存储目录互相包含或存在真实路径重叠；
  - 新目录与任一工具 Skills 目录重叠；
  - 新目录与任一本地原始 Skill 目录重叠。
- 已有托管 Skills 时先展示迁移确认，明确显示当前位置、新位置和受影响数量。
- 同步引擎独立校验源目录与目标目录，覆盖同步也不能绕过安全检查。
- 自动更新先比较新旧内容：内容未变化时只更新检查状态，不替换中央副本、不重建工具同步副本，也不计入“已更新”。
- 自动更新结果明确拆分为“已检查、无需更新、已更新、更新失败”四项；一轮结束后满足“已检查 = 无需更新 + 已更新 + 更新失败”，旧版已完成记录会自动补算“无需更新”。
- 内容变化检测使用“复制语义指纹”：按排序后的目录清单计算，区分文件和目录并记录明确的路径、长度、完整 Unix 权限位与内容边界；除复制时本就排除的 `.git` 外，所有会进入托管副本的文件都参与比较。
- 目标归属和回滚安全检查使用另一套“严格实际树指纹”，额外包含 `.git`、内部符号链接及其他特殊文件。即使用户只新增这些不会从源复制的内容，也会停止自动覆盖并保留现场。
- 自动更新先为中央副本和所有复制目标准备同目录临时副本，再将实际旧目录改名为应用内部备份并重新校验；只有更新前后两次校验都一致时才切换新副本，从而避免校验结束后目标又被修改的竞态窗口。
- 在应用进程正常运行期间，中央副本、所有已记录且未停用的复制目标和数据库元数据作为同一次更新处理。共享同一物理目录的多个工具记录只切换一次；任一目标校验、切换或数据库写入失败时，已经切换的目录全部恢复为旧版本。
- 回滚前会再次校验刚发布的新副本；如果工具恰好在切换后写入内容，新写入不会被永久删除，而是保存在同目录恢复副本中并报告冲突。
- 同一中央仓库使用跨进程更新锁，整轮定时更新与手动更新互斥；真正执行时发生锁冲突的任务会停止，系统任务触发阶段仍可能短暂显示为已排队。
- 复制目标缺失时，只有源 Skill 确实变化才重新创建；复制目标内容或文件类型与预期不符时，保留现场、停止覆盖并将该目标标记为需要人工处理。
- 存储迁移先完成全部预检和复制，再刷新链接，最后在同一数据库事务中更新 Skill 路径与存储设置。
- 迁移失败时恢复旧链接；只有回滚成功后才清理未完成的新副本，避免再次造成数据丢失。
- 修改自定义工具目录时，若新目标与本地原始目录重叠，立即停止保存；旧工具目录、当前配置和原始文件保持不变。
- 停用、取消同步、删除 Skill 和迁移旧目录继续使用安全清理逻辑：真实内容进入系统回收站，链接只解除链接。自动更新不复用这条用户移除路径。
- 删除托管 Skill 时始终保护已记录的本地原始目录。

### 异常终止边界

上述整体回滚覆盖应用仍在运行时能够收到的文件、校验和数据库错误。操作系统强制结束进程、断电或系统崩溃不会执行进程内回滚；本次修复不把它描述为跨崩溃事务。应用内部备份使用明确前缀保留，不会进入系统回收站，也不应在无法确认归属时自动清除。后续如需覆盖这一边界，应增加持久化更新日志和启动恢复流程。

## 提示优化

自定义工具目录发生重叠时，不再展示后端英文错误和冗长路径，统一提示：

> 无法保存：所选工具目录会与本地原始 Skill 目录重叠。为避免覆盖或移除源文件，请选择一个独立目录。原始文件未被修改。

Skills 存储设置同时增加常驻说明，引导用户选择独立目录，不要使用任何 AI 编程工具的 Skills 目录。

## 安全行为

| 场景 | 处理结果 |
| --- | --- |
| 新存储目录与工具目录或本地原始目录重叠 | 阻止修改，不迁移文件 |
| 自定义工具的新目录与本地原始目录重叠 | 阻止保存，旧配置和旧目标保持不变 |
| 旧目标是符号链接或 Windows 目录联接 | 只移除链接，不影响链接目标 |
| 自动检查发现 Skill 内容未变化 | 不替换中央副本和工具目标，不计入“已更新” |
| 查看自动更新结果 | 分别显示已检查、无需更新、已更新和更新失败，并解释每项含义 |
| 自动更新目标与更新前中央副本内容一致 | 使用可回滚的原子替换，旧托管副本不进入系统回收站 |
| 自动更新目标缺失 | 源 Skill 确实变化时重新创建目标 |
| 自动更新目标内容或文件类型与预期不符 | 保留目标并标记错误，不自动覆盖、不进入系统回收站 |
| 应用正常运行时，自动更新任一目标或数据库写入失败 | 中央副本和已切换目标全部回滚；并发新写入保存在恢复副本 |
| 手动更新与定时更新同时触发 | 后到的任务停止并提示已有更新进行中 |
| 用户操作中需要移除 Skills Hub 创建的真实副本 | 移入系统回收站 |
| 旧目标实际是本地原始目录或 Hub 托管源目录 | 保留目录，不执行删除 |
| 存储迁移中途失败 | 回滚链接和数据库状态，保留可恢复的数据副本 |

## 验收

1. 使用独立目录作为新的 Skills 存储路径时，已有托管 Skills 需要用户明确确认后迁移。
2. 选择任何工具 Skills 目录、本地原始 Skill 目录或当前存储目录的父子目录时，应用阻止迁移。
3. 修改自定义工具目录并使用复制模式时，新目录同步成功，旧副本进入系统回收站，本地原始目录保持不变。
4. 把自定义工具目录改到本地原始 Skill 的上级目录时，保存被阻止，并显示友好的中文提示。
5. 停用、取消同步或删除 Skill 时，符号链接只解除链接，真实副本进入系统回收站。
6. 存储迁移发生复制、链接刷新或数据库更新失败时，不产生部分生效的配置。
7. PR 回归测试覆盖路径双向重叠、原始目录保护、回收站调用、迁移事务和自定义工具目录冲突；`npm run check` 全部通过。
8. 自动更新检查到相同内容时，“已更新”为 0，中央副本和工具目标保持不变，系统回收站不新增目录。
9. 自动更新真实变化且复制目标仍与旧中央副本一致时，目标原子替换成功；正常清理成功时不遗留临时目录和回滚备份。
10. 自动更新发现复制目标被修改、替换成链接或其他非预期类型时，保留目标内容并显示需要人工处理的错误。
11. 多个复制目标中后续目标失败时，中央副本和此前已切换目标恢复旧内容，数据库仍记录旧版本，且不遗留临时目录。
12. 目标在临时副本准备完成后又被修改时，更新使用改名后的实际旧目录重新校验，保留用户修改并停止覆盖。
13. 同一中央仓库同时触发两个更新时，只允许一个任务进入文件切换阶段。
14. 两个工具记录指向同一物理复制目录时，该目录只替换一次，两条数据库记录同时更新。
15. 只修改脚本执行权限时应识别为内容变化；回滚期间的新写入应保存在恢复目录中。
16. 目标只新增 `.git`、内部符号链接或特殊文件时，也必须视为用户修改并停止覆盖；回滚期间新增这些内容同样保留。
17. 自动更新统计分别显示“已检查、无需更新、已更新、更新失败”，且四项数量关系一致；旧版已完成记录也能正确补算“无需更新”。
