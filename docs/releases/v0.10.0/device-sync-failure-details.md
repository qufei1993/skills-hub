# 设备同步失败原因

## 修复

- 顶部在最近一次同步失败时持续显示原因及处理建议，只匹配该次记录，避免展示旧失败。
- 失败历史可展开/收起原因，不展示无意义的全零变化统计。
- 手动同步失败后立即刷新活动状态，不重新加载仓库选择器或清空设置草稿。
- 保留公开上传确认、仓库可见性及凭据前置条件的原有控制提示。

## 安全边界

读取完整错误链识别网络、安全连接、鉴权、系统凭据、仓库读取/推送、完整性校验、私钥检测及本地存储错误。只保存固定白名单诊断码，不保存原始错误链、URL、Token、响应正文或文件内容。无法分类时提供明确的未知原因提示，不猜测或回显原文。

旧历史在读取时转换为安全诊断码，不清理或重写旧数据库内容。前端仅翻译已知诊断码，不显示任意错误字符串。同步与检查接口的异常也经过安全转换；无需新增凭据读取、数据库表或迁移。

## 验证

- 回归测试先复现缺失原因展示、手动失败后状态不刷新和原始凭据进入历史记录。
- 覆盖展开/收起入口、未知/缺失/包含敏感内容的旧错误、底层原因识别、持久化前保护及历史读取保护。
- 标准 `npm run check` 全部通过：125 项前端测试、319 项 Rust 测试，以及 lint、类型检查、生产构建、格式检查和 Clippy。构建保留原有动态导入/大分块提示。
