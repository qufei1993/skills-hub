# v1.0.0 官网合集安装

[English](website-collection-install.md) · [PR #185](https://github.com/qufei1993/skills-hub/pull/185)

## 安装流程

从官网打开合集后，可在 Skills Hub 中查看 Skills 和来源。合集既可以来自同一个 GitHub 仓库，也可以组合多位作者的仓库，每个来源均使用指定的提交版本。

打开链接仅校验并展示清单，用户确认后才开始安装。Skills 会加入技能库，也可选择工具进行全局分发，默认不选工具。已有同源 Skills 保持不变，冲突会明确提示；失败项可重试，不会重复安装成功项。工具分发失败时，可继续重试分发，无需重新安装 Skill。

如果手动添加界面处于空闲状态，会收起该界面并保留表单内容，显示合集确认窗口。正在执行的操作与其他确认窗口会先完成，再显示合集确认。临时让出确认窗口时保留安装进度与失败重试记录，Windows 与 Unix 的仓库目录分隔符均可匹配。

## 桌面唤起与平台支持

协议注册随桌面安装包交付，旧版用户需要升级到 v1.0.0 或更高版本。

- **macOS**：有效链接会显示、恢复并置前主窗口，应用已运行或最小化时同样适用；无效链接不会激活窗口。单独运行开发进程不会注册系统协议，需要使用应用包验证系统唤起。
- **Windows 和 Linux**：通过单实例机制将链接转交给已运行的窗口。后台定时更新进程不受单实例锁影响。Debian 安装包补齐协议注册所需的桌面工具依赖；注册失败不会阻止桌面启动，包启动验证使用独立桌面会话。

## 链接协议与安装保护

官网通过 `skills-hub://install?manifest=<编码后的 JSON>` 传递安装清单。v1 清单包含合集标题、以 40 位提交哈希固定版本的 GitHub 来源，以及选中的 Skill 名称和目录。

官网与桌面内清单共用最多 2,000 个 Skills、100 个来源的限制；外部链接编码后仍不得超过 30,000 字节。移除官网入口遗留的 100 项限制后，Aaron 的 120 项营销技能合集可完整打开安装确认。回归测试使用官网已发布的清单，保留固定提交版本和目录路径。

官网安装请求失败时，会显示保留到用户关闭的错误说明，明确原因和处理方法。链接清单太大时，可减少选择分批安装，或从「添加 Skills」中打开合集；清单版本不支持时提示更新应用。未选择 Skills、重名或重复项目、安装信息有误、清单无法读取及接收失败分别给出对应说明。系统错误窗口无法打开时，使用可关闭且不会自动消失的通知；未知内部错误仅显示安全的处理建议。

清单校验会拒绝不支持的版本、不安全路径、凭据、多余参数、重复项目或名称、未固定提交版本的来源及超长请求。接收链接不联网、不访问凭据；确认安装后复用既有安装服务、操作锁和应用代理设置，无需迁移数据库。
