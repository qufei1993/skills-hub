# 停用后重新启用 Skills，恢复原有工具选择

[English](skill-enable-recovery.md)

停用 Skill 会移除工具中的同步目录，但保留原先的工具记录。此前重新启用只检查工具是否被检测到，没有检查它是否已在「工具」页关闭。遇到已关闭但仍被检测到的工具时，会报 `TOOL_NOT_INSTALLED` 并中断恢复，导致 Skill 开关已经开启，其他保存的工具仍未同步。批量错误在翻译前拼接了标题，也使内部错误代码直接出现在提示中。

单项和批量启用现在只恢复原先选择且当前允许使用的工具。已关闭、已移除的工具和未检测到的全局工具会被跳过，保存的记录继续保留。项目同步恢复到原先的项目目录，并继续检查工具是否支持项目范围；不会自动增加新检测到的工具。

某个目标恢复失败时，其他工具和 Skills 会继续恢复。失败提示明确对应的 Skill 与工具，并单独翻译错误原因。单项操作无论成功还是失败都会刷新状态，包括停用后部分目录清理失败的情况。

历史工具路径也可正常恢复。例如旧 Cline 记录使用 `.agents/skills`，当前工具使用 `.cline/skills`。目标已停用且旧目录条目已移除时，重新启用可在工具当前配置的路径重建同步，并更新记录；旧条目仍存在或记录仍在使用时继续阻止变更。当前目录冲突、归属、来源重叠和内容检查继续生效。工具路径变更与同名目录冲突分别提示，提供中英韩说明。

回归测试覆盖全局及项目停用/启用往返、选择保留、跳过不可用工具、单项及批量中的独立目标失败、可读错误提示、清理失败后的状态刷新、历史路径恢复及保留已有或仍在使用的旧目标。不需要数据库迁移，也不调整版本号。
