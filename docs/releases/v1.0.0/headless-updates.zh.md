# 后台更新无窗口启动

[English](headless-updates.md) · [#152](https://github.com/qufei1993/skills-hub/issues/152) · [PR #193](https://github.com/qufei1993/skills-hub/pull/193)

系统定时更新和「立即更新」继续由独立进程执行。后台进程不再创建 Skills Hub 窗口；macOS 在事件循环启动前设置禁止激活策略，避免 Dock 短暂出现通用的 `exec` 图标。

原实现中，Tauri 在应用的 setup 回调前就创建配置窗口。macOS 的激活策略也在启动后才设置，随后更新同步占用这段启动流程。本次在运行时配置中禁用窗口创建，并在 `run` 前设置激活策略，不将更新搬到桌面主进程。

## 修复时的验证

- 在 macOS 上使用开发版桌面可执行文件和临时测试数据复现。临时观测代码仅重定向数据路径、输出 Tauri 窗口数量，并让 setup 停留四秒以便观测；不改变窗口创建及激活策略。
- 使用 AppKit/CoreGraphics 对子进程 PID 每 10 毫秒采样。修复前：创建一个窗口、屏幕可见窗口一个，出现普通应用激活策略。修复后：创建和可见窗口均为零，仅出现禁止激活策略，空测试库更新正常完成。
- 回归测试覆盖后台窗口禁用、普通启动窗口配置不变及精确参数匹配。窗口禁用用例修复前失败、修复后通过。
- `npm run check` 通过：网络边界、lint、377 项前端测试（另有一项跳过）、构建、Rust 格式与 Clippy、672 项 Rust 单元测试和 21 项集成测试。当时的开发构建版本一致性校验通过。
- `npm run tauri:dev` 使用独立前端端口、临时测试路径和独立应用标识启动；原生检查确认普通启动有一个可见窗口，激活策略为普通应用。提交前已移除临时观测代码，独立只读评审无阻塞问题。
- Windows 的窗口表现仍需原生 Windows 环境验证，macOS 实测不等于 Windows 实测。

对应 #152，参考 SanjiFlip 在 #155 中对窗口创建时机的调查，并遵循评审要求保留独立后台执行。
