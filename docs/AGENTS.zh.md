本文件是[英文规则入口](../AGENTS.md)的中文对照；项目指令以英文版为准，修改时同步维护两份文件。

## 沟通与任务范围

- 项目规则文件使用英文，并在 `docs/` 下维护对应的中文说明。每个文件的正文只使用一种语言；命令、路径、代码标识符和专有名称保持原样。
- 实现前简要说明方案和涉及文件。用户已授权的任务直接继续，不重复确认；需求、范围或不可逆操作的授权不清楚时再询问。检查和建议类请求保持只读。
- 只修改任务涉及的内容，保留用户已有改动，不顺带重构或清理无关代码。

## 项目入口

Skills Hub 是管理和分发 AI 技能的跨平台桌面应用，使用 React、TypeScript、Tauri 和 Rust。依赖版本、编译选项和检查命令以 [package.json](../package.json)、[Cargo.toml](../src-tauri/Cargo.toml) 及对应配置文件为准。

| 共用业务逻辑 | `src-tauri/src/core/` |
| 命令行入口 | `src-tauri/src/cli/`、`src-tauri/src/bin/skillshub-cli.rs` |

## 实现约定

- 前端通过 Tauri 的 `invoke` 调用桌面命令。新增命令须在命令层定义并在 `lib.rs` 注册；同步更新 `src/components/skills/types.ts` 与后端传输类型，命令参数沿用 `camelCase`。
- 命令层负责参数、传输类型和错误转换，业务逻辑放在 `core/`；异步命令中的阻塞工作使用 `tauri::async_runtime::spawn_blocking`。新增核心模块需在 `core/mod.rs` 导出；Rust 库名为 `app_lib`。
- 前端沿用现有组件、局部状态和钩子的职责，不把所有状态强行集中到 `App.tsx`，不为局部修改引入状态管理框架。
- 弹窗关闭时按交互需要处理状态重置、焦点和资源清理；组件自身返回 `null` 不等于该组件被卸载。
- 沿用现有错误分类和转换约定，使用 `anyhow::Context` 保留原因；用户反馈应说明失败状态和恢复操作，不能仅靠短暂通知承载必要信息。
- 界面文案必须使用国际化资源，并同步提供英文、简体中文和韩文。英文和中文资源在 `src/i18n/resources.ts`，韩文在 `src/i18n/ko.ts`。
- 样式沿用修改区域的现有组织方式，使用语义类名和 `src/index.css` 中的主题变量。涉及布局、视觉、共享组件、导航、浮层、响应式或交互反馈时，先读 [UI 设计规范](UI-DESIGN-GUIDELINES.md)；其他任务无需加载。
- 路径处理保留 `~` 展开能力；技能分发保留符号链接、Windows 目录联接、复制的回退顺序。新增工具适配时同步维护 `tool_adapters/mod.rs` 的工具标识和适配器注册。

## 开发与交付

1. **工作分支**：继续现有任务时沿用工作分支。开始独立的新开发任务且用户未指定基线时，获取 `origin/main` 并从它创建 `codex/` 分支；保留已有工作、核实基线，切换后按锁文件同步依赖。
2. **完整实现**：涉及前后端的功能，同步完成命令注册、传输类型、界面和三语文案，避免只交付其中一层。
3. **验证**：缺陷修复须有能检出旧问题的回归测试。开发中可运行针对性检查；完成修改后执行 `npm run check`，提交前确保检查对应最终改动。完整步骤和构建前置条件见贡献指南，不以局部检查替代完整检查，不把受阻或未运行记为通过。
4. **桌面复核**：修复用户可见问题后，从当前工作分支运行 `npm run tauri:dev` 并确认启动，除非用户另有要求；只复用或重启当前检出的开发进程。浏览器预览不能代替桌面原生行为验证。
5. **文档与版本**：遵循[变更与发布规则](../CONTRIBUTING.md#change-records-and-releases)，包括统一的中英文版本清单。目标发布版本未确定时，用户可见变更写入两份更新日志的 `Unreleased`。不把后续变更追加到已发布版本；普通小修复无需单独创建专题文档。项目要求的配套多语言更新属于当前任务；不额外翻译无关文档，发布记录无需韩文。未经要求不提升版本；版本一致性使用 `npm run version:check` 验证。
6. **提交与发布**：遵守用户对提交、推送和发布的要求。请求创建拉取请求时，目标为 `main`，优先更新当前分支已有请求，附带代码、测试及适用的更新日志和文档修改，并核实链接；未经授权不合并。

## 安全边界

- 令牌、密码和私钥只能存入系统安全凭据存储，禁止进入数据库、配置文件、日志、URL 或同步仓库。
- 只有用户主动操作或明确开启的后台功能才能读取凭据；页面加载、切换标签、状态展示和普通启动不得读取。
- 开发版使用独立的凭据命名空间；授权、凭据、同步相关改动必须通过防泄漏与访问边界测试。
- 开发版桌面和命令行与正式版共用数据库、中央技能目录、配置、缓存、回收站和写锁，操作会影响真实工具目录。凭据和命令行桥接程序使用独立开发命名空间；自动化测试使用临时数据和工具目录，旧开发库不得自动合并或覆盖正式库。

## 网络与数据兼容

- 生产环境的 HTTP 客户端、OAuth 请求和远端 Git 操作必须通过 `src-tauri/src/core/network_proxy.rs` 创建或配置，显式使用应用代理设置；禁止依赖进程代理环境变量、Git 全局代理或在业务模块中直接创建传输客户端。
- 新增或修改出站网络代码后运行 `npm run network:check`，不得通过路径、命名或测试标记绕过检查。
- 数据库变化沿用现有迁移机制。旧版本可安全忽略的新增功能表，使用 `settings` 中独立的功能模式标记，不提高共享的 `PRAGMA user_version`。
- 每次数据库迁移必须包含升级测试和上一稳定版本兼容性测试；不兼容的共享模式变化须先明确兼容方案。
