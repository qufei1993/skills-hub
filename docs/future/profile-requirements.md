# 从配置方案到技能预设

状态：早期需求已由技能预设方案取代。2026-10-30 对照当前分支整理；本次功能尚未发布，软件包版本仍为 1.0.1。当前行为统一维护在[实施说明](../releases/v1.1.0/implementation.zh.md#skill-presets)，本页保留需求来源与取舍，不作为新增开发任务。

## 原始需求与最终选择

早期围绕技能分组讨论了 `Profile / 配置方案`：把同一工作场景所需的 Skills 和工具保存起来，减少重复配置。标签用于查找和分类，配置组合用于复用成员与工具关系，两者并不替代。

最终采用“技能预设（Preset）”。预设保存成员及逐成员工具分配；使用时由用户明确选择全局或项目。一个 Skill 可以被多个预设引用，同一目标也可以先后应用不同预设，不存在唯一的“活动预设”。浏览、编辑或删除预设不会改变已经部署的 Skills。

| 早期建议 | 当前决定与原因 |
| --- | --- |
| 单选激活 Profile，切换时替换整套同步配置 | 采用主动应用、保留无关部署的预设。用户可能混用多个组合和手动添加项，切换不应隐式卸载它们。 |
| 为整套组合保存一个共同工具集合 | 保存每个成员的工具映射，避免把成员与工具取笛卡尔积而扩张部署范围；统一工具仅是明确选择的便利操作。 |
| 首页展示当前 Profile 和配置编辑入口 | “我的 Skills”负责已安装内容与目标管理，组合创建、编辑和应用集中在“技能预设”，减少重复入口。 |
| Profile 绑定项目或进入项目时自动应用 | 预设定义不绑定项目路径，应用时选择位置；切换项目只改变视图。 |
| 提醒用户处理未加入 Profile 的 Skills | 没有加入预设是正常状态，不增加未分配提醒。标签仍承担分类和筛选。 |
| 用 `is_active` 和独立 Profile 关联表保存活动配置 | 实现采用工作区文档和 `schema.workspace` 功能标记，不引入活动 Profile 模型。旧 SQL 草案不再适用。 |

## 编辑之后如何生效

修改预设只更新组合定义；原来应用过的位置保持不变。需要补充成员或工具时，用户主动再次应用。移出预设的成员、手动添加项和其他预设的部署不会自动移除。应用记录保存当时的结果，不代表项目持续跟随预设。

执行前检查冲突；部分失败保留已经成功的目标，未完成项通过原记录重新检查。撤销依据实际新增及后续使用情况，不能把整个项目恢复成某次预设快照。历史保留、清理和撤销边界见[技能预设实施说明](../releases/v1.1.0/implementation.zh.md#skill-presets)。

## 保留的范围边界

本次不包含自动跟随、互斥切换、自动卸载预设外内容、继承与优先级、在线分享、预设跨设备同步或新增预设 CLI 命令。这些不是待补齐的隐含需求；只有出现明确使用场景并重新确认范围后才评估。
