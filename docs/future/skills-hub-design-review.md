# 项目、技能预设与更新的设计决策

状态：2026-10-30 对照当前实现整理，功能尚未发布。本页记录早期原型之后的主要取舍；完整行为、数据保护与实现位置统一维护在[实施说明](../releases/v1.1.0/implementation.zh.md)。固定[设计稿](../releases/v1.1.0/design.md)和[原型评审](../releases/v1.1.0/design-review.md)保留为历史基线，next 草稿不属于本次功能。

## 页面职责与操作流程

“我的 Skills”用于管理已有内容和部署位置；“添加 Skills”负责发现和导入；“技能预设”负责保存、编辑和复用组合。这个划分保留项目管理能力，同时避免首页出现多个添加、配置和保存入口。AI 设置与本机发现提示独立于 Skill 列表，分别支持关闭，不计入搜索结果和技能数量。

预设保留常驻列表、详情和编辑页。应用是一项短任务：从卡片或详情打开同一弹窗，选择全局或项目，默认使用保存的成员与工具，再执行应用。临时调整按需展开。普通无冲突应用不再经过单独的“检查计划”页面，但后端仍在写入前生成并校验计划。

| 原方案的问题 | 当前选择 | 取舍 |
| --- | --- | --- |
| 为复用一套已保存组合，仍要逐页选择成员、工具和检查计划 | 默认沿用预设，在同一窗口选择位置；调整仅影响本次应用 | 减少重复确认，冲突、明确移除和撤销仍保留必要检查。 |
| 为所有条目展开工具、绝对路径和共享目录明细 | 默认显示成员及工具摘要，具体调整和部署详情按需展开 | 常用流程更紧凑，需要排查时仍能找到位置与原因。 |
| 全部冲突时仍提示“继续应用其余 Skills” | 区分全部受阻与部分可执行；显示具体工具、路径、原因，并保留返回后的选择 | 用户能判断下一步，不用不可执行按钮暗示还有可处理内容。 |
| 首页同时管理部署和编辑、保存组合 | 预设操作集中到技能预设页，项目卡片保留目标管理 | 入口更清楚；首页不提供重复的组合编辑流程。 |
| 把模板当作持续生效的项目配置 | 编辑仅修改定义，应用是明确的一次操作 | 不会因模板修改而悄悄改变部署；也不承诺自动同步或自动卸载。 |

新建、编辑、复制和删除预设不写入部署。成员与工具按原映射保存，不把两者分别取并集。失效成员需要明确处理，不能静默替换。取消或返回保留相应上下文，未保存编辑有放弃保护，弹窗关闭后焦点返回触发位置。

## 历史与撤销的作用

应用记录用于解释结果、继续未完成项和安全撤销新增目标，不是永久审计日志。当前保留最近更新的 100 条已确认且所有项目均进入终态的记录；未完成或状态不确定的操作额外保留。这样控制存储增长，又保留必要的恢复依据。被裁剪的记录不能再撤销，但裁剪不会卸载文件或删除后续使用标记。取消未执行的预检查会清理临时记录，已确认或有写入证据的操作继续保留。

撤销只处理仍属于本次新增的目标。原有或修复的部署、被后来操作复用的目标、个人修改、目标换代及共享目录引用都需要保护。编辑或删除预设不改写历史，也不授予额外撤销权限。精确规则以[预设与数据保护](../releases/v1.1.0/implementation.zh.md#skill-presets)为准。

## 更新页面的取舍

更新页以“检查来源 → 处理变化”为主线，默认只列有变化的 Skills，恢复快照另设页签，自动更新计划和执行记录保持独立。进入页面读取已有摘要，不自动访问所有来源；手动检查对同一 Git 仓库与分支复用刷新结果。检查期间保留旧列表，完成后持续显示数量、失败、时间和实际耗时，避免只闪一下就无法判断结果。

“全部更新”或“更新所选”提供直接操作，查看差异是可选步骤。执行前的校验仍不可跳过，旧缓存和已失效结果不能授权写入。差异通过行号、增删高亮和折叠上下文表达，文件权限变化单独展示，不再要求用户比较两段完整文本。

内容恢复与部署撤销分开：每个 Skill 保留最近一次成功更新前的内容及来源元数据，恢复检查后续修改并保留后来新增的目标。这满足误更新恢复需求，不扩展成任意版本历史。详细检查、取消、部分失败与恢复行为见[更新与恢复](../releases/v1.1.0/implementation.zh.md#updates-and-recovery)。

## 实施与证据边界

上述行为已经进入当前分支的 React/Tauri/Rust 实现，不能再描述为“只有 HTML 原型”。预设仍仅保存在本机，未新增预设同步或预设 CLI 命令。固定原型中的任务耗时、试用者理解率和布局矩阵属于当时的目标或原型证据，不代表当前产品已重新完成同样的验收。
